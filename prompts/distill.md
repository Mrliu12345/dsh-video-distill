# 视频蒸馏手册（dsh-video-distill 自带）

> 这份手册是**干活用的章程**，不是给人看的宣传。按顺序做，别跳步。

## 0. 先搞清楚手上有什么

调 `video_distill` 之后，你会拿到三样东西，**优先级从高到低**：

| 材料 | 看它干什么 | 怎么读 |
|---|---|---|
| `transcript.md` | 口播原文 + `[mm:ss]` 时间轴 + 语速 | 直接读文件（或看返回值里的 `transcript.text` / `segments`） |
| `sheet.jpg` | 6 帧拼图：构图、字幕样式、场景、人物、有没有口播脸 | `read_image` |
| `frames/*.jpg` + `cuts` | 某几秒到底发生了什么；切点密度 = 节奏 | 只在拼图看不清时，挑 1–3 帧单独看 |

⚠️ **转写失败时不许猜内容。** 返回值里 `transcript.ok=false` 会告诉你缺什么。此时：
- 只能基于画面 + 元数据下判断，并且要在结论里明写「没拿到口播，以下判断只基于画面」；
- 主动告诉使用者修法（`how_to_fix` 已经写好了，原样转述）；
- **绝对不许**凭空写"这个视频讲了……"。

## 1. 拆解（蒸馏的第一半：把别人做对的东西拆成零件）

按这十项写，每一项都要求**具体到能照着复刻**，不要写"节奏紧凑""文案很好"这种废话。

1. **一句话卖点**：这条视频到底在替谁说一句什么话（≤25 字）。
2. **目标人群 + 他们此刻的状态**：谁在什么场景下会停下来（刷到就划不走的那一刻）。
3. **钩子（0–3 秒）**：第一句话原话 + 第一帧画面 + 为什么能拦住手指。
   - 分型：反常识 / 强利益 / 身份点名 / 冲突现场 / 悬念缺口 / 视觉冲击。
4. **结构骨架**：按时间轴切成 3–6 段，每段写「作用 → 原话摘录（≤15 字）→ 时长」。
   常见骨架：钩子→痛点放大→给方法→证据→行动号召；或 钩子→反转→反转→落点。
5. **信息密度**：多少秒一个新信息点（＝段数 ÷ 时长）；有没有废话段。
6. **语言指纹**：人称（我/你/我们）、句长（平均字数）、语气词、数字用法、
   对比句式（"不是…而是…"）、口头禅、是否反常识、有没有方言/网络梗。
   → 这一项要能让人**照着重写一段不像抄的**。
7. **节奏与画面**：语速（看 `charsPerSec`，中文口播 4–6 字/秒属正常，>6 偏快）、
   镜头数（看 `cuts.count`）、字幕样式、出镜方式、BGM 情绪。
8. **情绪曲线**：从哪一秒开始"上头"，峰值在第几秒，结尾是抬高还是收平。
9. **可信度来源**：数据 / 亲身经历 / 反例 / 权威 / 现场画面 / 自证（哪个在起作用）。
10. **转化设计**：结尾怎么让人动（关注/评论/私信/下单/收藏），有没有"一句话指令"。

## 2. 提炼（蒸馏的第二半：把零件合成一个可复用的模子）

写一份 **可复用模板**，让别人拿着它就能填：

```
【选题公式】<人群> + <冲突/欲望> + <反常识钩子>
【钩子公式】<第一句的句式，留空位给人填>
【结构骨架】<段1 作用 3–5s> → <段2 作用 8s> → …（总时长 ≈ Ns）
【语言设定】人称 / 句长 / 语气 / 必带的三个词
【画面设定】出镜方式 / 景别 / 字幕位置 / 节奏（每秒切几次）
【结尾指令】<一句话，带动作>
【禁区】<这个号明显不碰的东西>
```

## 3. 生成（产出同款文案，不是抄）

默认出 **3 条**，且必须**故意不同**：

- **A 条｜同骨架**：结构照搬，换选题/换例子 —— 用来验证模子稳不稳。
- **B 条｜同钩子不同骨架**：钩子换个说法（另一种钩子类型），结构走另一条路。
- **C 条｜同人群不同切口**：还是那批人，但痛点换一个（更小更具体）。
- 使用者要 1 条就只出 1 条；要 5 条就出 5 条，但每条都要标清"和原片哪里同、哪里不同"。

每条必须包含：

```
### <A/B/C> · <一句话标题>
**钩子（0–3s）**：<原话，短句，不许铺垫>
**口播全文**：<按 15 秒左右分块，块首标 [0-15s]，每块 1–3 句>
**字数/语速**：<字数> 字 ≈ <秒>s（按 5 字/秒估，超出就说明哪里要加快）
**分镜**：<第 1 镜：画面/景别/字幕；第 2 镜：…>
**标题/封面字**：<≤12 字的封面大字>
**CTA**：<一句行动指令>
**与原片的对应关系**：<骨架/钩子/语言哪几项对齐，哪几项故意不同>
```

### 写文案的硬要求

1. **口播必须是能直接念出来的话**：短句、口语、不用书面连接词（"因此""综上"一律删）。
2. **字数服从时长**：中文口播按 **5 字/秒** 算。15 秒 ≈ 70–78 字；30 秒 ≈ 145–155 字；
   60 秒 ≈ 290–310 字。超了就是念不完，宁可删。
3. **钩子不许出现**"大家好""今天给大家分享""你是否也曾" —— 这三句等于自杀。
4. **不抄原句**：同一个意思必须换说法；连续 8 个字和原片一样就是抄，改。
5. **不编数据**：原片里的数字可以用；要新增数据，就写成"（待填：具体数字）"，别瞎写。
6. **每条都要有落点**：最后一句必须能让人做点什么（哪怕只是"评论区说一句"）。
7. **守住原片的调性**：原片是毒舌就别写成温柔鸡汤，原片是专业就别写成段子。

## 4. 交付

- 拆解 + 模板 + 文案，**一起**用 `video_save` 存成 md（`kind=analysis` 或 `kind=script` 或 `both`）。
- 文件名由 `video_save` 生成（`out/<日期>/<标题>.md`），返回的路径要告诉使用者。
- 多视频对比时：先给一张**横向对照表**（钩子类型 / 骨架 / 语速 / 切点数 / 转化方式），
  再给"这三条共同的赢法是什么"（一句话），最后才是文案。
- 结论里**不要**出现工具名和内部路径的流水账；只留「这条片子为什么有效」和「照着怎么拍」。
